## 合并与读取

Excel 以明确的主键合并，突破记录使用角色或武器编号与突破等级组成的联合键，好感奖励使用角色编号与好感等级。旧行的值、类型和顺序均保留。

现有点位按点位 ID 追加；坐标、传送位置和类型随配置保留，原有点位和顶层配置保持不变。怪物模型索引使用 `monsterName + monsterId` 与真实文件名逐项核对。

Ability、Talent 和角色模型保留原有目录结构，现有定义保持不变。未确认字段继续保留原名称。

## 校验

- 全部 263 个变更资源 JSON 均可解析，226 个新增文件逐字节核对通过。
- 99,176 条原有记录和 1,720 个原有大世界点位的值及类型保持一致。
- 全部 3,517 个怪物模型索引、点位使用的副本引用核对通过。
- 使用 AstaPS 的 `JsonUtils`、`ResourceLoader` 和 `onLoad` 实际读取配置；两名新角色的技能组、命座材料、90 级属性、默认 Ability 和好感名片均通过检查。
- Scene3 经实际点位加载器读取到 1,819 个点位。
- 重复运行同步检查不会产生资源改动。

结果见 [校验记录](runtime-7.2-validation.json)。这些检查覆盖资源结构、依赖和服务端读取，尚未进行真实客户端的完整玩法验证。

## 同步检查

通用同步脚本接受本地快照路径和本地 Git 引用：

```sh
python3 scripts/sync_runtime_resources.py \
  --source /path/to/local-snapshot \
  --source-ref SNAPSHOT_REF \
  --check
```

使用 `--apply` 应用增量。同步脚本不会修改已有记录；运行状态保存在本地 `.git` 中。
